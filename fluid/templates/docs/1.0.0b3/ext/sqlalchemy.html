Extensions

SQLAlchemy

In this chapter we will talk about one of the most important features of a web application: Databases! We are assuming that you are already familiar with SQLAlchemy V2 and only explain how to work with our built-in sqlalchemy extension.

Your first model

Like Flask-SQLAlchemy our extension does provide its own Model class. So you do not need to set up your own DeclarativeBase. But of course you are not forced to stick with ours. We will show you a quick example of using your own db instance in the end of this chapter.

For now let's just get started by creating your first simple model:

{{ code( "fluid/models.py", "python", '''from webfluid.core.ext import db from sqlalchemy.orm import Mapped, mapped_column class MyModel(db.Model): id: Mapped[int] = mapped_column(primary_key=True) value: Mapped[str] def __init__(self, value: str): self.value = value''' ) }}

Integrating SQLAlchemy

Now you can start using your model inside your application. Our extension provides sync and async utility. So when you configure your database uris, do not add the driver package to the uri string. The framework does that for you. So your config should look like this:

{{ code( "app_configs/app.ini", "ini", '''[general] SECRET_KEY = supersecret [data] DATABASE_URI = sqlite:///app.db [extensions] EXT_SCHEDULING = 0 EXT_SQLALCHEMY = 1''' ) }}

Our SQLAlchemy extension will then derive the sync and async engine with their correct driver from your database uri. We provide this functionality for the most common dialects: sqlite, postgresql and mysql.

Only the leading scheme is rewritten, so a path segment, a database name, a user or a password that happens to contain the word sqlite, postgresql or mysql comes through untouched.

Both engines are created lazily, on the first executor that actually needs them. So a bind you only ever touch synchronously never opens an async connection pool on the side. Whatever you put into SQLALCHEMY_ENGINE_OPTIONS is forwarded to both of them; it defaults to { "pool_pre_ping": True, "pool_recycle": 3600 }. And what is opened lazily is closed deliberately: the extension registers a shutdown hook that disposes the sync and the async engine of every bind, so a stopped app leaves no pool behind it.

What survives the block

Look closely at the add_model handler above: it builds its response inside the executor. It does not have to. Both session factories run with expire_on_commit=False, which means the rows an executor hands you keep their loaded column values after it commits and closes. So this reads just as well:

{{ code( "example", "python", '''async with db.async_executor(model=MyModel) as e: model = await e.insert(MyModel(value), flush=True) # The session is closed and committed by now, but the row is still readable: return {"model_id": model.id, "value": model.value}''' ) }}   {{ info(""" What does not survive is anything the row has not loaded yet — a lazy relationship, for instance, has no session left to load itself from. Load what you need while the executor is open, then take the object with you. """) }}

Now you have successfully integrated SQLAlchemy into your application. But you may want to find out what the hell that db.get_bind_for_model(MyModel) is...

Working with binds

Like Flask-SQLAlchemy our extension is able to handle multiple binds using bind keys. You can define binds by setting MyModel.__bind_key__ and adding the SQLALCHEMY_BINDS dictionary to your config.

Here we have a quick example of wiring it all up:

{{ code( "app_configs/app.ini", "ini", '''[general] SECRET_KEY = supersecret [data] DATABASE_URI = sqlite:///app.db TEST_DB_URI = sqlite:///test.db [extensions] EXT_SCHEDULING = 0 EXT_SQLALCHEMY = 1''' ) }} {{ code( "fluid/models.py", "python", '''from webfluid.core.ext import db from sqlalchemy.orm import Mapped, mapped_column class MyModel(db.Model): id: Mapped[int] = mapped_column(primary_key=True) value: Mapped[str] def __init__(self, value: str): self.value = value class SecondModel(db.Model): __bind_key__ = "test" id: Mapped[int] = mapped_column(primary_key=True) value: Mapped[str] def __init__(self, value: str): self.value = value''' ) }} {{ code( "main.py", "python", '''from webfluid import Fluid from webfluid.core.config import register_config from webfluid.core.ext import scheduler, db from fastapi import Request from fastapi.responses import HTMLResponse from fastapi.exceptions import HTTPException from apscheduler.triggers.interval import IntervalTrigger from sqlalchemy import select import os from extension.main import MyExtension from fluid.jobs import heart from fluid.models import MyModel, SecondModel @register_config(10) class MyConfig: SESSION_COOKIE_SECURE = True MYEXT_BAR = "crazy" SQLALCHEMY_BINDS = { "test": os.getenv("TEST_DB_URI", "sqlite:///test.db") } fluid = Fluid(__name__) my_ext = MyExtension(fluid) scheduler.add_job(heart, IntervalTrigger(seconds=5)) @fluid.get("/", response_class=HTMLResponse) async def home(): return await fluid.render( "index.html", title="Hello World!", name="my friend" ) @fluid.get("/health") async def health(): return {"status": "ok"} @fluid.get("/my-model") async def get_model(request: Request): model_id = request.query_params.get("id") if not model_id: raise HTTPException(status_code=400, detail="Bad Request") # The context manager resolves the correct bind for you: async with db.async_executor(model=SecondModel) as e: results = await e.exec( select(SecondModel).where(SecondModel.id == model_id) ) result = results.first() if not result: raise HTTPException(status_code=404, detail="Model not found") return { "model_id": model_id, "value": result.value } @fluid.post("/my-model") async def add_model(request: Request): data = await request.json() value = data.get("value") if not value: raise HTTPException(status_code=400, detail="Bad Request") async with db.async_executor(model=SecondModel) as e: model = await e.insert( SecondModel(value), flush=True ) return { "model_id": model.id, "value": model.value } if __name__ == "__main__": # bind = db.get_bind_for_model(MyModel) # bind.metadata.create_all(bind.sync_engine) bind = db.get_bind_for_model(SecondModel) bind.metadata.create_all(bind.sync_engine) fluid.mix()''' ) }}

Notice that we create the tables through bind.metadata and not db.Model.metadata here. Every bind keeps its own metadata, so a model that is attached to a bind key lives in that bind's metadata, not in the default one. For the default bind the two are the same, which is why the single database example above could get away with db.Model.metadata.

Dynamically setting binds

In some cases you may want to define the bind of your model dynamically. For example, by using a config value. Then you would use MyModel.set_bind and do something like this:

Changing table names

As you may have already thought, SQLAlchemy resolves table names by converting your models' name to snake case like the Flask extension does. And so you can change the models' table name by setting __tablename__ as well:

{{ code( "fluid/models.py", "python", '''from webfluid.core.ext import db from sqlalchemy.orm import Mapped, mapped_column class MyModel(db.Model): id: Mapped[int] = mapped_column(primary_key=True) value: Mapped[str] def __init__(self, value: str): self.value = value class SecondModel(db.Model): __tablename__ = "my_table" __bind_key__ = "test" id: Mapped[int] = mapped_column(primary_key=True) value: Mapped[str] def __init__(self, value: str): self.value = value''' ) }}

Reusing the current executor

An executor is more than a context manager — it is a proper context, tracked per task. So besides opening a fresh one, you can reach the executor that is already open in the current scope. That matters as soon as your code stops living in a single handler: the moment a handler calls a helper that also touches the database, you have to decide whether that helper gets its own transaction or joins the one you already have.

Three tools cover that:

  • db.current_executor / db.current_async_executor — the executor open in this scope, or a RuntimeError if there is none.
  • db.ensured_executor(...) / db.ensured_async_executor(...) — yield the current executor if one is open, otherwise open a new one. Reach for it when you are not sure a session exists yet and don't want to force a second one.
  • Executor.outer() / AsyncExecutor.outer() — from inside a nested executor, step back into the one that was open before it.

The everyday tool is ensured_async_executor. Write your helpers with it and they work either way — standalone, or folded into a caller's transaction:

{{ code( "example", "python", '''from webfluid.core.ext import db from sqlalchemy import select, func from fluid.models import MyModel async def count_models() -> int: # Joins whatever executor is open around us, opens one if none is. async with db.ensured_async_executor(model=MyModel) as e: result = await e.exec(select(func.count(MyModel.id)), scalars=False) return result.scalar()''' ) }} {{ code( "example", "python", '''async def add_and_count(value: str): async with db.async_executor(model=MyModel) as e: await e.insert(MyModel(value), flush=True) # One session, one transaction: the count already sees our insert, # because count_models joined the executor instead of opening # a second one that would not see uncommitted rows. return await count_models()''' ) }}

current_async_executor is the sharper version of the same idea: it does not open anything, it just hands you the active executor and raises if there is none. Use it when the caller must have opened one — it turns a silent second transaction into a loud programming error.

  {{ warning(""" Do not assume the framework left a session open for you. Dependencies that load something from the database — the Security battery's current_user, for instance — deliberately release their connection before handing you the result, so they do not hold a pool slot for the whole request. In a route handler there is no current executor unless you opened one, which is exactly why the ensured_ variants exist. """) }}

Finally the case the context nesting was built for: you open a new executor for a model on a different bind, but still need the outer session for a moment. Opening the new executor makes it the current one, so outer() is how you reach back:

{{ code( "example", "python", '''from webfluid.core.ext import db from webfluid.extensions.sqlalchemy import AsyncExecutor from fluid.models import MyModel, AuditEntry # AuditEntry sits on the "audit" bind async def record(value: str): async with db.async_executor(model=MyModel) as outer: model = await outer.insert(MyModel(value), flush=True) # A brand new session for the audit bind becomes the current one: async with db.async_executor(model=AuditEntry) as e: entry = AuditEntry(model_id=model.id, action="created") await e.insert(entry, flush=True) # Step back into the model session for a moment without # closing this one. outer() is a plain (sync) context manager: with AsyncExecutor.outer() as outer_e: model.value = f"{value} #{entry.id}" await outer_e.flush() return entry.id''' ) }}   {{ info(""" outer() swaps the active executor back to the enclosing one for the duration of the with block, then restores the inner one. It is a synchronous context manager even for AsyncExecutor, since it only moves the context pointer — not the session. Pass a depth to step back more than one level, and expect None if there is no outer executor. """) }}

Leave the framework defaults

Like we've mentioned earlier, you are not forced to stick with our defaults. You can wire up extensions yourself if you do not want to rely on WebFluids conventions. Keep in mind that this may break the frameworks' functionality if you do not know what you are doing.

Anyway, we will show you how to escape from our conventions with the SQLAlchemy extension. The same counts for every other built-in extension as well. So in the following chapters we will only tell you what parameters you can pass to our extensions if you want to leave their defaults.

Okay, but now let's set up your own conventions. The SQLAlchemy extension only supports passing your own DeclarativeBase. So this will be exactly what we are doing:
